# P2.31–P2.36 Dashboard UX 全面改版

## 目標

把 Dashboard 從「技術資料總表」改為「交易日期與階段清楚、可在手機快速判讀的決策中心」。
固定策略與歷史樣本不因介面改版而重寫；介面只增加保守的顯示／通知安全阻擋。

## 已完成階段

### P2.31 日期、階段與安全狀態

- 將同一個看盤交易日拆成三條生命週期：當日 09:15 判斷、下一交易日準備、D2+ 後續觀察。
- 每張候選卡顯示形成日與判斷日；歷史日期顯示「封存紀錄」，不得冒充今日建議。
- 移除易誤解的 `D0 次日可交易 YES/NO`，改為等待、完成、阻擋等中文狀態。
- 停損價未低於觸發價、風險距離超過 5%、報價／官方風險資料不足、處置與公司行動，一律顯示不介入。
- 固定策略的原始狀態不改寫；另存 `ux_trade_blocked`、原因代碼與風險幾何欄位，供介面與通知一致使用。

### P2.32 每日決策中心與手機導覽

- `market.html` 改為預設入口，盤後預設開啟「下一交易日準備」，盤中預設開啟「當日 09:15 判斷」。
- 手機提供固定底部導覽，桌機保留頂部導覽；控制項高度至少 44px。
- 候選由寬表格改為卡片；動作、日期、觸發／停損、理由、板塊與風險依閱讀順序排列。
- 主畫面只保留決策必要內容；技術狀態移至系統狀態頁。

### P2.33 個股生命週期與通知一致性

- 個股詳情顯示 EPS、處置、公司行動、資料狀態、來源與策略版本。
- 個股 D0 → D1 → D2+ 歷程改為使用者展開後才載入。
- Telegram D1 名單使用同一套安全阻擋，不再把危險停損幾何的股票列為可觀察。
- D1 新資料新增穩定原因代碼；前端不再依完整英文句子才能翻譯。

### P2.34 資訊分頁

- `rules.html`：固定規則、板塊確認與一票否決條件。
- `validation.html`：先顯示能否證明有效，再分開呈現日線回測、分鐘線覆蓋、固定基準與影子策略。
- `status.html`：排程、資料新鮮度、公開頁面與 Telegram 送達狀態。
- `index.html`：直接導向每日決策中心，移除舊版隱藏的重複每日看盤區塊。

### P2.35 載入效能與錯誤復原

- 初次只載入日期索引、所選日期、前一交易日與輕量狀態資料；不再一次抓取全部歷史日檔。
- 歷程展開後才載入歷史，單一日期失敗時以部分成功結果繼續顯示。
- 區分零候選、篩選後無結果與資料載入失敗；載入期間顯示骨架並停用相關控制。
- 驗證頁與系統頁使用獨立容錯，單一摘要檔失敗不使整頁空白。

### P2.36 驗收與發布

- 自動測試涵蓋日期配對、缺前一交易日、缺 09:15 報價、官方風險缺漏、處置、公司行動、停損矛盾、風險超過 5%、D2 失效與英文下一步翻譯。
- 實際檢查桌機與 390px 手機版：不得水平溢出，手機導覽持續可見，階段分頁可用鍵盤方向鍵切換。
- 每次發布前執行 JavaScript、Python、靜態資料與公開頁面驗收。

## 不在本階段範圍

- 不啟動券商下單、自動買進、自動更換固定策略或自動調參。
- 不因介面阻擋而回寫或刪除既有 `p2.11_v2` 紙上交易樣本。
- 影子策略仍只在中期或正式門檻達成時通知人工審查。
